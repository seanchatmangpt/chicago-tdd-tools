# AGENTS.md — Chicago TDD Tools

This file is the normative operating contract for repository agents.

## Constitutional equation

`A = μ(O*)`, followed by `R = receipt(A)`.

- `O` is partial or stale observation.
- `O*` is admitted, aligned, complete, grounded, and bounded observation.
- `μ` is lawful manufacturing.
- `A` is an artifact with standing.
- `R` is the consequence receipt and replay anchor.

No implementation claim outranks observed execution evidence.

## Law-state route

`parse → route → admit/refuse → diagnose/repair → manufacture → authorize → actuate → receipt → replay/hook`

The broker is the only actuation authority. Hooks manufacture intents; hooks never perform direct side effects. Zero unreceipted actuation is a hard invariant.

## ggen authority

The authored source of truth is RDF/Turtle plus `ggen.toml`, templates, SPARQL extraction queries, and `O.star.toml`. Files under a declared `generated/` root are products, not sources.

- Never hand-edit generated files.
- Run generation twice and require byte identity.
- Verify generated bytes independently from Turtle, queries, templates, manifest, verifier, tests, process evidence, and the previous receipt.
- Permanent validation is read-only and fail-closed.
- Receiver-facing evidence must be attached to the exact candidate head.
- Pin the real ggen execution graph to exact repository commits and one Rust toolchain.

The manufacturing lifecycle is:

`Resolve → Enrich → Extract → Render → Write → Receipt`

Admission is not standing. Candidate, verified, authorized, actuated, and receipted are distinct states.

## Combinatorial maximalism

The governing refactor calculus is:

`exact observation → admitted semantic model → bounded candidate lattice → deterministic composition → verification → explicit authorization → brokered actuation → observed consequence → causal receipt → independent replay`

The canonical architecture cell is `architecture/combinatorial-maximalism/`.

- One pure shared kernel owns composition law.
- Existing modules are realizations, not independent architecture authorities.
- Internal maximalism covers implementations, runtimes, storage modes, protocols, projections, and verification rails.
- External maximalism covers published protocols and consumer contracts without private dependency or authority leakage.
- The pure kernel has no filesystem, process, network, provider SDK, credential, deployment, or broker authority.
- A plan is never an execution grant.
- A hook is never a broker.
- Generated output is never semantic authority.
- Local standing is never external standing.
- Maximum lawful consequence is preferred over maximum output volume.

Every selected realization projects across exactly ten axes:

`strategy × process × role × data × application × technology × control × evidence × deployment × consumer`

The enterprise profile remains bounded to 512 projection consequences. Any overflow refuses with `CMD-PRJ-001`.

The architecture pack is:

`Pack = SemanticKernel + Operators + Projections + Contract + Lifecycle + Evidence`

The standards cell is the constitutional pack. The legacy root operator-registry manifest remains a compatibility adapter. New architecture work must enter through the profile-driven kernel rather than adding another parallel registry.

## Chicago TDD discipline

Prefer state-based tests against real collaborators. Use deterministic fixtures. A test double must never fabricate success at an external boundary. Assertions must prove observable consequences, not merely that a call returned `Ok`.

Verification expands only after narrower proof succeeds:

`unit → integration → e2e → chaos → stress → benchmark → verifier report`

## Gall states

Use only: `PARTIAL_ALIVE`, `ALIVE`, `BLOCKED`, `BUILD_BROKEN`, `UNKNOWN`, `UNSUPPORTED`.

- `ALIVE` requires observed execution.
- `UNKNOWN` is not admitted.
- `UNSUPPORTED` is not refused.
- A checkpoint must not be overclaimed as crown completion.
